# J2 — Runtime architecture alternatives and controller-interface prior art

Research date: **14 October 2026**. **INFERRED recommendation: a bounded C → B → ROS-output sequence**: establish retained-data replay/conversion, qualify the existing native runtime, then expose ROS outputs. Design controller rejection semantics early; implement the wire sender after estimate semantics exist. The proposed “ROS pose/health node + Pi–STM32 contract + logger first” is useful eventually, but its ordering is not yet justified.

Labels apply to each marked paragraph and table cell: **SOURCE-SUPPORTED** = inspected source/specification; **MEASURED** = dated repository evidence, not a measurement performed here; **INFERRED** = engineering interpretation/recommendation; **ASSUMED** = proposed experimental choice; **UNKNOWN** = unresolved. This is a research proposal, not an approved API or architecture change.

## 1. Starting evidence and scope

**MEASURED:** [13 Oct facts][F13] report native ORB-SLAM3 EuRoC MH01 ATE RMSE 0.0368–0.0416 m, but undervoltage confounds speed. [14 Oct addendum][F14] reports the 8 GB Pi, continued undervoltage, large gaps in a 100-second card take, clean delivery in a 15-second RAM take, first-frame replay SIGSEGV, and an interrupted fix rebuild. **INFERRED:** storage blocking explains the card gaps; neither ROS overhead nor calibrated D435i live capability follows from these observations. **UNKNOWN:** successful post-fix replay, sustained capture-to-estimate age and robot fallback timing. `PROJECT_STATE`, `NEXT_GATE` and `EVIDENCE_INDEX` remain historical/draft summaries; newer dated observations take precedence.

**SOURCE-SUPPORTED, local code:** [recorder][REC] already selects stereo Y8 640×480/30, gyro/200, accel/100 and limits takes to 120 seconds. [SDK audit helper][RS] preserves timestamp domain, SDK milliseconds, host steady/UTC arrivals and motion precision. [association helper][INPUT] provides bracketed interpolation and bounded IMU queues. [example patch][PATCH] shares live/file input, disables real-time playback, bounds the image queue and logs tracking-call duration/state. It currently discards `TrackStereo`'s return value: a continuously published pose/state adapter still needs work. [analyze_take.py][ANALYZE], [plot_run.py][PLOT] and [trajectory evaluator][EVAL] already cover timing summaries, trajectory plots and ATE/RPE; do not rebuild those components.

**SOURCE-SUPPORTED, project policy:** build on [R1][R1] for engine/frame/calibration decisions, [R2][R2] for UART/COBS/CRC and receiver policy, and [R3][R3] for power/storage/gates. `R1b_algorithms_independent.md` was absent when inspected. STM32H7 owns body estimation, balance, LQR, VMC, FSM and motor safety; D435i and body IMUs remain separate ([ADRs][ADR]). Native SLAM does not waive N3. Preserve fresh N1, USB ≥5000M, exact N2 IR1 Y8 640×480/15 + gyro/200 + accel/100, 20→105→mandatory 300-second stages and existing thresholds; stereo/30 is separately qualified. Physical/ORB work requires `CAMERA AVAILABLE`; no such work occurs here.

## 4. Controller state: borrow semantics before inventing fields

**INFERRED recommendation:** refine R2's transport-independent health/estimate envelope; begin health-only. Reuse an existing proven MCU protocol if one exists (**UNKNOWN**). Otherwise retain R2's candidate UART/COBS/CRC transport pending board review. MAVLink supplies valuable semantics and generated tooling [MAVCODE], but adopting its complete wire protocol is justified only by an actual maintained receiver or interoperability need. Adding PX4/ArduPilot firmware to WBR is not implied.

| Prior art | SOURCE-SUPPORTED statement | INFERRED WBR consequence |
|---|---|---|
| MAVLink `ODOMETRY` [MAV] | `time_usec` permits epoch/boot time; pose and velocity frames are explicit; quaternion is **w,x,y,z**. Covariances use the 21-element upper triangle; first-element NaN means unknown. `reset_counter` increments on discontinuities including loop closure; `estimator_type` identifies VIO; quality: −1 failed, 0 unknown, 1–100 graded. | Explicit clock domain/session instead of magnitude guessing; reset plus map/frame epoch; quality availability separate from validity. ORB inlier count is not calibrated probability/covariance. Do not map unavailable quality to “100”. Counter wrap needs session/sequence handling. |
| PX4 external vision [PX4], EKF2 [EV][], [EVPOS][] | Capture-relative timestamps/timesync and `EKF2_EV_DELAY` matter; source checks quality, recent samples, reset and finite values, uses an innovation gate and stops timed-out EV fusion. | Receipt is distinct from acceptance/use. Receiver returns rejection reason/last accepted estimate; withdraw optional perception on rejection. Do not copy flight-controller rates, filter resets or timeouts into balance policy. |
| ArduPilot visual odometry [AP], `VISION_POSITION_ESTIMATE` [VISION] | ArduPilot prefers `ODOMETRY`, accepts VISION messages, documents ≥4 Hz input and ignores quality below `VISO_QUAL_MIN`. VISION_POSITION_ESTIMATE supplies Euler pose, covariance and reset counter; it lacks ODOMETRY's quality/type/velocity fields. ArduPilot's interface says sender boot time need not be synchronized to the autopilot. | Adopt reset/error/acceptance semantics, not its rate or clock assumption: those depend on ArduPilot's receive implementation. WBR must prove its own source-age mapping. Use the signed MAVLink quality definition; the AP table's unsigned type conflicts with −1. |
| ROS diagnostics [DIAG][], [UPDATER][] | Status levels OK/WARN/ERROR/STALE, hardware identity and key/value details; updater supplies frequency diagnostics; documented default period is one second. | Reuse for operator visibility. Separate process/link alive, sensor integrity, estimator initialized/tracking and estimate fresh. MCU freshness enforcement must not depend on diagnostics cadence. |
| `nav_msgs/Odometry` and covariance [ODOM][], [COV][] | Pose uses `header.frame_id`, twist uses `child_frame_id`; pose covariance is full row-major 6×6, ordered x,y,z, rotations X,Y,Z. These definitions specify no unknown-covariance sentinel. | Do not copy MAVLink's NaN rule or sensor_msgs/Imu's −1 rule into odometry without a consumer agreement. Supply valid covariance when available; otherwise expose pose with explicit uncertainty-unavailable health and withhold fusion-ready odometry. Never manufacture zero certainty. |

**INFERRED minimum envelope:** version, Pi boot/session, packet and estimate sequences, acquisition epoch/domain, mapped epoch plus uncertainty, send epoch, frame/transform revision, reset/map epoch, estimator identity/state, validity/reason flags and uncertainty availability. Pose/twist are optional until correctly transformed to the robot body. ROS quaternion order is x,y,z,w; conversion must be explicit [ROSQUAT]. Every stamped field names its clock: device capture, Pi monotonic processing/send, ROS time for replay, MCU monotonic reception/expiry; UTC is provenance. A heartbeat never advances estimate sequence or source time.

**INFERRED receiver policy:** validate framing, bounds, session/sequence, finite values, frames, age and state before updating accepted state. Reject duplicates, stale epochs, excessive clock uncertainty and reset discontinuities; expire using MCU monotonic time. Withdraw autonomous references through the controller-owned fallback while its local body estimator and balance loop continue. Bounded parsing/mailboxes must not block balance. Reset/reboot requires re-establishment rather than automatic navigation resumption. Reuse R2's fault ladder; add frozen-estimate/fresh-heartbeat, delay, map jump, wrap, malformed data, bridge death and Pi loss cases. **UNKNOWN:** approved age/timeout/loop-jitter budgets and actual physical balance survival. No architecture alone proves it.

## 6. Executor and QoS pitfalls at the actual rates

**SOURCE-SUPPORTED:** Jazzy executor documentation describes middleware queues, round-robin/non-FIFO scheduling under backlog and potential priority inversion [EXEC]. Callback groups control parallelism; the default is mutually exclusive, so merely selecting a multithreaded executor does not parallelize those callbacks [GROUP].

**INFERRED:** ingestion callbacks should enqueue bounded data and return; one ordered worker calls tracking. Separate ingestion/health from tracking, bag writes, map saving and blocking services. Multiple executor threads plus ORB workers can oversubscribe four CPU cores; measure thread demand before affinity tuning. Health must report stalled tracking even while callbacks remain active.

**SOURCE-SUPPORTED:** best-effort publisher plus reliable subscriber is incompatible; sensor QoS trades completeness for timely delivery, while reliability may retry. DDS deadline/liveliness/lifespan describe messaging rather than physical source age [QOS]. **INFERRED:** inspect actual QoS and record overrides. Keep image queues small/bounded; retain the entire required IMU integration interval, including brackets. At 200 Hz, one sample period is **ASSUMED arithmetic: 5 ms**; stereo/30 is 33.3 ms, with about 6–7 gyro and 3–4 accel samples per image interval. Derive IMU buffer capacity from maximum admitted delay plus bracketing, not an arbitrary depth shared with images. Count missing samples and invalidate broken intervals; best effort does not authorize silent IMU loss. Reliable QoS does not repair sensor/storage loss. Pair stereo by original capture epochs/skew; do not nearest-match IMU to one image or assume executor receipt order equals capture order. Replay isolated, preserve headers and enable `/clock`/`use_sim_time` consistently [BAG].
