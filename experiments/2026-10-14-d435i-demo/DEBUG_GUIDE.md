# D435i VIO log triage (offline evidence only)

Likely causes below are hypotheses, not diagnoses. Inspect retained files on
the Mac; preserve raw logs/calibration warnings. Set `RUN` to a local result
directory and `TAKE` to a local copy containing the recorder's timestamp audit.
No commands here start ORB-SLAM3 or a camera. Any later acquisition/replay remains
subject to `CAMERA AVAILABLE` and N1 → N2 → N3, including the unchanged 300-second
N2 soak, exact raw profile and timing thresholds.

| Log symptom | Likely causes and source evidence | One check to run |
|---|---|---|
| `Not enough motion for initializing. Reseting...` | Little translation during early inertial refinement; stationary/pure rotation or bad visual poses. This message occurs **after IMU initialization**: accumulated motion time <10 s and the sum of two inter-keyframe camera distances <0.02 m triggers reset; only distances >0.05 m advance that time. [LocalMapping.cc:129–144](../../third_party/ORB_SLAM3/src/LocalMapping.cc#L129). | `python3 experiments/2026-10-14-d435i-demo/plot_run.py "$RUN"`; inspect initial keyframe spacing in the plot. Body/IMU export spacing is a proxy for the source's camera-center distance; full-run extents cannot prove early excitation. |
| Repeated `Creation of new map` | Track loss, a backward camera timestamp, or a >1 s jump can create/reset maps. One creation at startup is normal, and **two printed lines describe one creation** ([Atlas.cc:58–74](../../third_party/ORB_SLAM3/src/Atlas.cc#L58)). Backward timestamps create a new map at [Tracking.cc:1820–1826](../../third_party/ORB_SLAM3/src/Tracking.cc#L1820); LOST can do so at [Tracking.cc:2271–2286](../../third_party/ORB_SLAM3/src/Tracking.cc#L2271). | `rg -n -B 12 -A 2 'Creation of new map with id:' "$RUN"/*.log`; inspect the preceding event for each new map ID, rather than counting both creation messages. |
| `Fail to track local map!` | Insufficient visual correspondences: low texture/light, blur/rapid motion, stereo pairing/rectification errors; wrong calibration or IMU timing can also corrupt prediction. The log means tracking returned false, not a unique root cause ([Tracking.cc:2125–2131](../../third_party/ORB_SLAM3/src/Tracking.cc#L2125)); IMU stereo requires ≥15 inliers in this branch ([Tracking.cc:3046–3050](../../third_party/ORB_SLAM3/src/Tracking.cc#L3046)). | Manually inspect one retained left/right stereo pair at the first failure: sharpness, texture, common frame/time, and row correspondence if rectified. If images were not retained, this check is **OPEN**; a plot cannot establish image quality. |
| No IMU initialized / `Not IMU data in mlQueueImuData!!` | Missing/unbracketed accel/gyro, wrong timestamp units/domains, insufficient stable keyframes/excitation, wrong `IMU_STEREO` mode or IMU geometry/noise assumptions. Empty queue returns without integration ([Tracking.cc:1634–1640](../../third_party/ORB_SLAM3/src/Tracking.cc#L1634)); stereo initialization needs ≥10 temporal keyframes and ≥1 s ([LocalMapping.cc:1185–1211](../../third_party/ORB_SLAM3/src/LocalMapping.cc#L1185)). The initialized flag is set at [LocalMapping.cc:1295–1300](../../third_party/ORB_SLAM3/src/LocalMapping.cc#L1295); absence of an exact “IMU initialized” string alone is inconclusive in upstream logs. | `python3 experiments/2026-10-13-n4b-d435i-prep/analyze_take.py "$TAKE/timestamps.csv"`; verify nonempty Gyro/Accel, expected rates, gaps/order and a common SDK domain. This is an acquisition audit only; ORB input bracketing/interpolation and calibration remain separate unresolved checks. |
| `Frame with a timestamp older than previous frame detected!` / timestamps backward | Device clock reset, concatenated takes, replay out of order, mixing SDK/host clocks or units. ORB clears the IMU queue and creates a map ([Tracking.cc:1820–1826](../../third_party/ORB_SLAM3/src/Tracking.cc#L1820)); >1 s jumps have separate reset handling ([Tracking.cc:1828–1850](../../third_party/ORB_SLAM3/src/Tracking.cc#L1828)). | `python3 experiments/2026-10-13-n4b-d435i-prep/analyze_take.py "$TAKE/timestamps.csv"`; inspect `nonpositive_steps` and `domains` per stream. Recorder SDK time is **ms**, ORB input **s**, EuRoC trajectory export **ns**, TUM GT **s**. Never sort raw records to hide reversals; acquisition order does not alone establish ORB delivery order. |

Source pin: local ORB-SLAM3 `4452a3c4ab75b1cde34e5505a36ec3f9edcdc4c4`.
Use the cited line numbers with this pin. Keep under-voltage/thermal/USB evidence
beside each failure: those faults can cause stalls but do not identify the VIO
root cause. Fix the evidenced input/platform problem; do not loosen initialization,
tracking or gate thresholds to obtain a success label.
