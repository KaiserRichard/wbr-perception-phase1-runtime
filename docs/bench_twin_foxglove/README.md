# Recorded live bench twin for Foxglove

This adds one JSON-schema MCAP of side-stream overlays for the archived camera
and MuJoCo twin runs. It does not combine/rewrite those input MCAPs.

## Open the replay

1. In Foxglove, open `~/wbr-evidence-archive/lab-day-20261025/3-box13/camera-bag/camera-bag_0.mcap`, `~/wbr-evidence-archive/foxglove-twin-20261030-01/twin.mcap`, and `~/wbr-evidence-archive/bench-twin-foxglove-20261030-01/bench_twin.mcap` together as one data source.
2. Import `docs/bench_twin_foxglove/layout.json` from the Layout menu.
3. Play/seek the shared timeline. The MCAP preserves the camera packet epoch for advisory, jump phase, leg length and twin scene. The IMU has a separately recorded clock and requires an explicit chosen offset.

Make the extra MCAP with an explicit alignment choice (example `0` seconds):

```sh
VENV=~/Desktop/Research/wbr-lab-ops/.venv
"$VENV/bin/python" tools/bench_twin_foxglove/make_mcap.py \
  ~/wbr-evidence-archive/bench-twin-foxglove-20261030-01/bench_twin.mcap \
  --imu-offset 0
```

The output is never overwritten. `--imu-offset` is required and measured in seconds from the first
IMU sample to the first camera packet. It does not establish synchronization.

## Evidence labels

- **MEASURED:** camera packet advisory/height/distance and frame stamps in
  `packets.csv`; IMU acceleration/gyro CSV values and filter-derived pitch,
  roll and rates; CAN STAT counters and ESR from `run-02/raw.log`; populated
  motor feedback fields if the feedback CSV has rows. CAN and feedback were
  separate captures, so their offsets onto camera time are **ARBITRARY**.
- **CALCULATED:** CAN rates and error-counter deltas are differences of the
  recorded cumulative STAT counters; tilt is the existing complementary filter
  in `tools/imu_view/filter.py`.
- **SYNTHETIC:** jump phase, leg lengths and gate confidence are a research
  replay generated by `tools/jump_gate/timeline.py`; its inputs include assumed
  telemetry and its raw confidence is ASSUMED as documented there. The located
  `canfix05-home-01/motor_fb.csv` contains a header but no samples, so the output
  uses clearly labelled synthetic zero feedback. Twin cuboid/leg/wheel geometry
  and dimensions are ASSUMED schematic presentation values.
- **ARBITRARY alignment:** IMU and camera were captured separately. The explicit
  `--imu-offset` shifts IMU sample time relative to the first camera packet;
  neither this offset nor the separate CAN capture offset is synchronization
  evidence. The twin MCAP already uses camera packet stamps.

## Parameter provenance

Every input/derived/display parameter carries a source label in message fields or
above: camera epoch and CSV values are MEASURED; filter output and counter rates
are CALCULATED; gate/twin geometry and zero feedback are SYNTHETIC/ASSUMED; the
IMU time offset is an explicit ASSUMED user choice and the cross-capture alignment
is ARBITRARY. `jump_at` defaults to 20 s as a SOURCE-SUPPORTED convention in
`tools/jump_gate/timeline.py`, not a detected physical jump.
